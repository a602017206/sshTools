# JDBC 内置清单迁移设计

## 背景

JDBC 驱动清单首次启动时会复制到 `~/.sshtools/drivers/manifest.json`。现有实现只在该文件不存在时写入内置清单，因此旧应用生成的清单永远不会获得新的达梦和人大金仓在线安装 profile。

## 方案

内置清单增加递增版本号。`ensureManifest` 读取现有清单并比较版本：

- 清单不存在时写入完整内置清单。
- 已有清单版本低于内置版本时，以内置驱动定义为基准合并更新同 ID 的 driver 和 profile。
- 保留现有清单中内置没有的自定义 driver/profile，避免删除用户离线导入或自定义来源。
- 已有版本相同或更高时不修改文件。

合并完成后使用临时文件和原子重命名提交，继续保持 `0600` 权限。

## 验收

- 旧达梦 `dm-8` / 金仓 `kingbase-8` 清单自动迁移为带 Maven Central URL 和 SHA-256 的新 profile。
- 金仓 V8/V9 都出现在迁移后清单中。
- 自定义 driver 保留。
- 新版清单不会在每次启动时重复改写。
