# 原生数据库工作区改造设计

## 背景

原生数据库连接复用了终端容器的深色背景，但原生资源面板在浅色主题中继续使用深色文字变量，造成 Redis、Elasticsearch 等连接后的内容难以辨认。首版界面也只提供无提示的资源树，用户无法分辨 Redis 的逻辑库、ES 索引以及哪些资源可进一步展开。

## 决策

`NativeDatabasePanel` 作为独立内容工作区，显式使用应用主题的背景、边框和文字变量，不再依赖终端容器的视觉语义。所有原生类型共享资源卡片与状态布局，类型差异由一个纯前端展示模型定义。

Redis 的逻辑库允许展开读取键；MongoDB、Cassandra 和 Couchbase 的一级资源允许展开；Elasticsearch 索引、Memcached 统计项、InfluxDB Bucket、Neo4j 数据库和 Kafka Topic 作为只读叶子资源展示。叶子资源不再发起空的子资源请求。

## 范围与限制

本次修复全部原生数据库类型的可见性和资源浏览体验，并明确 Redis 与 Elasticsearch 的当前只读能力。不会增加 Redis 键值读取/修改、ES 文档查询/编辑或其它服务的写操作；这些功能需要分别定义权限、数据量与查询模型。
