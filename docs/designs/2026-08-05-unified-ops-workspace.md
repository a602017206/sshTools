# 设计：统一运维工作区

## 背景

现有界面以终端为唯一中心，连接、文件、监控和数据库能力分别存在，但缺少统一的资源入口和全局概览。此次改造以用户确认的高保真原型为目标，将桌面客户端组织为可切换的工作区。

## 目标与用户

面向同时维护 SSH 主机与数据库的开发者和运维人员。首屏的唯一任务是让用户在不打开终端的情况下确认连接、资源负载和下一步操作；深度工作仍在终端、文件和数据库工作区完成。

## 视觉系统

- 墨蓝底色：`#09111e`；工作区表面：`#101d31`；抬升表面：`#14243b`。
- 信号色：`#39d5e8`，仅表示当前工作区、实时链路和主操作。
- 状态色：成功 `#70d6ab`、警告 `#f0b865`、异常 `#fb7185`。
- 正文使用系统中文无衬线字体，遥测和终端数据使用等宽字体。
- 记忆点为一条细的“命令脉冲线”：在活动标签和实时指标中以低频动画提示数据正在流动；启用减少动画时完全静止。

## 信息架构

```text
+ 资源树 + 工作区标签 + 全局操作 +
| SSH / 数据库 / 容器 / 云资源            |
+------------------------------------------+
| 概览：健康度、连接、资源、快捷操作       |
| 终端：保留现有多会话终端                  |
| 文件：保留现有 SFTP 文件管理器             |
| 数据库：保留现有数据库工作区               |
| 性能：复用当前会话监控                     |
+------------------------------------------+
```

## 关键取舍

- 不虚构 Docker、Redis 或云端控制后端。资源树将这三类作为可展开的工作区入口与空状态，不向用户承诺未接入的执行能力。
- 不重写现有终端、SFTP 和数据库组件，使用工作区壳层将其重新编排，保护已经可用的会话逻辑。
- 概览的图形为从现有会话和连接状态派生的 UI 概览；无法取得实时监控时明确显示“连接服务器后查看实时数据”。

## 可用性要求

- 所有工作区标签为原生按钮并提供可见焦点。
- 颜色不作为唯一状态信息，连接行同时显示文字状态。
- 在较窄窗口中资源树和右侧检查器自动隐藏，内容区不产生横向滚动。
- 动画只使用 `transform` 和 `opacity`，并遵从 `prefers-reduced-motion`。
