# MySQL 对象树设计

## 背景

MySQL 原有数据库浏览页面只展示数据库和表列表，与 PostgreSQL 系列的 Schema 对象树不一致，也无法直接发现视图、存储过程、函数和事件。

## 目标

提供 `数据库 -> 对象分类 -> 对象` 的懒加载树，交互接近数据库客户端常见对象浏览器，并保持现有表结构和数据浏览入口。

## 方案

数据库根节点仍通过既有 `ListDatabases` API 获取。展开对象分类时，前端按需查询 MySQL `information_schema`：`tables` 读取基础表、`views` 读取视图、`routines` 区分存储过程与函数、`events` 读取事件。

表对象单击打开 DDL，双击继续派发既有表数据浏览事件。非表对象仅作为可浏览对象显示，不会错误调用表 DDL 接口。

## 风险

对象可见性取决于 MySQL 账号的元数据权限。事件和例程在部分托管 MySQL 服务上可能不可见，查询失败会在对象树中提示错误，不影响已加载节点。
