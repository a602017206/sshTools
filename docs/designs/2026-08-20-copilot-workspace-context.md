# 设计：Copilot 工作目录与会话上下文

## 背景

Shell Copilot 原先只能执行四条精确匹配的主机探测命令，无法识别当前目录中的启动或重启脚本。独立 SSH 命令会话也不会继承交互终端的当前目录；本地终端则既未可靠提供目录，也可能进入 SSH 探测路径。

## 方案

- 新增无参数的 `list_working_directory` 工具，只列出当前工作目录的文件、权限和大小。
- 工具命令由应用固定为 `cd -- <已转义目录> && LC_ALL=C command ls -la --`；模型不能控制命令、目录或命令连接符。
- `WorkingDir` 必须为绝对路径且不含 NUL。无有效目录时返回工具失败，不退化为用户家目录扫描。
- 本地会话记录创建时的工作目录，并可接受终端输出中的 OSC 7 路径更新；本地会话明确拒绝 SSH 独立命令执行。
- 每个会话保留最近 6000 个字符的终端输出。请求模型时一并发送，后端的 `Redact` 仍负责脱敏。

## 安全取舍

本次不开放任意只读 Shell，也不把“重启”自动执行。模型只可获取目录清单，生成的命令仍需用户点击执行，并经过既有危险操作确认。目录内容可能含密钥或配置，因此不读取脚本正文；模型只根据名称、权限和用户问题选择候选脚本。

## 限制

OSC 7 是否持续发送由用户 Shell 配置决定。本地会话至少能获得启动时目录；SSH 目录继续依赖已有终端 CWD 跟踪。对话历史仍只在当前应用内存中保留，关闭会话或重启应用会清除。
