# 文件夹上传拖垮 SSH 连接

## 背景

文件夹上传会让本应用卡死，同一台服务器用别的 SSH 工具也连不上。SFTP 和终端、监控共用一条 SSH TCP 连接。

## 原因

`UploadItems` 为每个文件立刻 `go startFileUpload`。一千个文件就是一千个 goroutine、一千个 transfer、一千条 Wails 进度事件。它们挤在同一个 `sftp.Client` 和同一条 SSH 上：

- 控制面 mkdir/stat/create 打满 `sftp-server` 和磁盘
- SSH 窗口被占满后，同一连接上的终端和监控也停
- 服务器过载后，新的 SSH 握手超时，所以别的客户端也连不上
- 前端给每个文件 `EventsOn`，WebView 卡死

## 决策

整棵目录树合成 **一次传输**，在后台 **串行**：先建目录，再逐个传文件。Wails 调用立刻返回，避免扇出。进度按「第 n/m 个文件」汇报。

不在本次改冲突检测的远程列举；新文件夹通常只 List 一次当前目录。

## 风险

大文件期间字节级进度变粗，只在每个文件结束时更新。共享 SSH 连接仍可能被大流量占满，但不会再被成千上万个并发请求打满。
