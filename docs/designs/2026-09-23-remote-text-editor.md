# 文件管理在线编辑文本和配置

## 背景

文件管理目前只能把远程文件下载到本地再打开。配置和脚本经常只改几行，来回下载上传容易覆盖服务器上的新内容，也不方便直接保存。

## 目标

- 在文件列表右键菜单中，对文本和配置文件提供「在线编辑」
- 弹窗编辑器按文件名和内容做语法高亮
- 「格式化」按类型整理文本，这次修改可以撤销
- Ctrl+S / Cmd+S 把当前内容写回原路径

## 范围

包含：

- 已知二进制扩展名不提供编辑；其余 1MB 以内的普通文件可以尝试打开
- 后端拒绝目录、超过 1MB、含 NUL 或不是 UTF-8 的内容
- 高亮覆盖 JSON、YAML、XML、HTML、CSS、JavaScript、Markdown、SQL、Python、Shell、Nginx、TOML、Dockerfile 和 properties
- 结构化格式化：JSON、YAML、XML/HTML、SQL；其余类型只去掉行尾空白并补上末尾换行
- 扩展名含糊时（如 `.conf`、`.txt`、无扩展名）先看内容再决定语言和格式化
- 保存优先用 SFTP `posix-rename` 替换原文件，并尽量保留原权限；不支持时退回原地覆盖
- 有未保存修改时，关闭弹窗需要确认

不包含：

- 本地会话（文件管理本身不用于本地 shell）
- 大于 1MB、二进制、非 UTF-8
- 多人同时编辑的锁和冲突合并
- 把双击从「本地下载打开」改成在线编辑

## 取舍

编辑器使用 CodeMirror 6。它自带撤销栈，格式化只要作为一次文档替换，Ctrl+Z 和工具栏「撤销」就能回到格式化之前，不必另做一份快照。

YAML 使用 `yaml` 的 `parseDocument`，避免 `js-yaml` 那种重新 dump 丢掉注释。JSON 用原生解析。XML/HTML 用轻量缩进，不引入完整的 XML 解析器。SQL 只在引号和注释之外、主要子句前换行，并保留关键字原来的大小写。

写回不用「先删原文件再改名」。`posix-rename` 可以替换已存在的文件；服务器不支持时再截断重写，临时文件在失败时删除。符号链接按打开后的目标写入，避免把链接本身换成普通文件。

换行在编辑器内部是 `\n`。打开时记住原文件是 LF 还是 CRLF，保存时按原样式写回，避免只打开再保存就把 Linux 配置改成另一种换行。

## 风险

- 没有 `posix-rename` 的服务器在写到一半失败时，原文件可能已经是截断后的内容
- XML 格式化按尖括号切分，属性值里的 `>` 或 CDATA 可能被拆开；可以用撤销恢复
- YAML 格式化仍可能调整引号和折行，注释应保留
- 未知扩展名会显示「在线编辑」，真正读到二进制时由后端拒绝
